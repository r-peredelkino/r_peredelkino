# Восстановление посадок перед ареной, v30

Этот каталог содержит исходное изображение, пиксельную трассировку и самостоятельный генератор `dist/arena-landscape-data.js`. Для обычной работы интерактивной карты Python не нужен: браузер использует уже готовый файл из `dist`.

## Состав

- `arena-source.png` — исходный экспорт панорамы застройщика, 1700 × 1200, без интерфейса браузера и без кадрирования.
- `source-pixel-overlay.svg` — те же пиксели с нанесёнными контурами клумб и ориентиров. Жёлтые точки обозначают предполагаемые основания деревьев под видимой кроной.
- `arena-source-trace.json` — камера, исходные пиксели, локальные сдвиги и результаты проверки контуров.
- `trace_arena.py` — трассировка, регистрация относительно имеющегося мощения и генерация данных сцены.
- `projection.py` — используемая формула преобразования лучей панорамы в XZ модели.
- `reproduction-check.json` — результат проверки воспроизведения окончательного файла v30 без записи в `dist`.
- `requirements.txt` — версии NumPy и Shapely, использованные при проверке.

Все необходимые файлы источника и проекции находятся в этом каталоге. Генератор не обращается к сети или к каталогам прежних выпусков. Он обнаруживает корень проекта по `dist/forecourt-reference-data.js`; имя корневой папки проекта и текущий рабочий каталог могут меняться.

## Проверка и повторная генерация

Проверка выполнена с Python 3.12, NumPy 2.5.3 и Shapely 2.2.0. В отдельном Python-окружении установите зависимости:

```sh
python -m pip install -r tools/arena-v30/requirements.txt
```

Из корня проекта проверить, что существующий runtime-файл воспроизводится:

```sh
python tools/arena-v30/trace_arena.py --check
```

Режим `--check` не записывает файлы. Он повторяет трассировку, проверки границ и сравнивает результат с текущим `dist/arena-landscape-data.js`. Итог содержит SHA-256 результата, количество объектов и локальные поправки.

Для намеренной повторной генерации:

```sh
python tools/arena-v30/trace_arena.py
```

Эта команда записывает ровно два файла: `dist/arena-landscape-data.js` и `tools/arena-v30/arena-source-trace.json`. Она читает имеющиеся `dist/public-realm-layout.js`, `dist/complex-footprints.js` и `dist/forecourt-reference-data.js`. При смене версий геометрической библиотеки возможен иной порядок представления равнозначных контуров; зафиксированные версии предназначены для воспроизведения проверенного результата.

## Источник и метод

Источник: [панорама застройщика от 29 июня 2026 года](https://pano.life-fly.ru/rodina/peredelkino/2026-06-29/), узел `node1`. Параметры экспорта: pan −37°, tilt −37°, горизонтальный FOV 58°, north 123.58°, 1700 × 1200 пикселей. Предполагаемая высота камеры над плоскостью земли — 60 м.

Проекция использует ту же привязку и масштаб, что существующий проект. В `pixel_to_world` параметр `height` задаётся в метрах исходной системы; высоту из единиц сцены нужно сначала разделить на `SCALE`.

Новые данные включают девять клумб, пять деревьев, семь белых светильников, девять фрагментов тонких линий, белое сидение и одну пару кафе-зонтов. Их геометрия дополнена оценкой высоты растений; она не получена из BIM-модели или геодезического обмера.

Четыре клумбы размещены непосредственно по лучам панорамы. Пять контуров смещены на 0,25–2,25 единицы сцены, чтобы сохранить форму в существующей более узкой пешеходной полосе. Каждый сдвиг записан в `registrationShift`. После смещения сохранено более 99,5% трассированной площади; растительность не выходит на проезжую часть и отделена от архитектуры зазором. Площадь 292,42 относится к квадратным единицам сцены, а не к обмеренной площади участка.

Подробный визуальный аудит и CPU-проверка находятся в `tools/qa-v30/landscape-b-visual-corrections.md` и `tools/qa-v30/landscape-fidelity-b-results.json`.
