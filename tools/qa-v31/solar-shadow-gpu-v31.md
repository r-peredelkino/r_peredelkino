# Проверка реальных GPU-теней: v31

## Назначение и текущий статус

Это отдельная калибровочная страница, которая запускает **настоящий** `dist/architectural-lighting.js`, его `solar-shadow-camera.js` и PCFSoftShadowMap в браузере. Она не подменяет тени изображением, Canvas-рисованием, аналитической маской или результатом CPU-raycast. Аналитическая маска используется только после GPU-рендеринга как независимый ожидаемый результат.

Выполнена CPU-проверка синтаксиса, построения фигур, ориентации плоскости, соответствия камеры мировым координатам, аналитических лучей и чувствительности классификатора. Результат сохранён в `solar-shadow-gpu-review.json`: восемь сцен и 23 244 сравнения с действительными треугольниками Three.js. Идеальные контрольные изображения принимаются; изображение полностью пропавшей тени отвергается в каждом случае.

После CPU-подготовки основной агент запустил драйвер на установленной кандидатной v31 на Mac. Итоговый отчёт `solar-shadow-gpu-native-results.json` содержит **PASS: восемь рабочих случаев и два обнаруженных негативных контроля**. GPU — `ANGLE (Apple, ANGLE Metal Renderer: Apple M2, Unspecified Version)`, WebGL 2, Three.js r170, shadow map 4096×4096. Во всех десяти случаях `glError = 0`; список ошибок страницы пуст. Время запуска в отчёте — 11 октября 2026 года, 10:01:58–10:02:01 UTC.

Исторический CPU-отчёт сохраняет свой статус `CPU_REVIEW_PASS_GPU_PENDING`: он документирует отдельный этап подготовки, а итог native-проверки находится в новом отчёте. SHA-256 четырёх загруженных модулей (`architectural-lighting.js`, `solar-shadow-camera.js`, `solar.js`, `vendor/three.module.js`) сверены с текущими файлами `dist` и совпали.

## Измеренный native-результат

В восьми рабочих случаях нет расхождений в 6 483 436 пикселях, уверенно находящихся внутри солнечных или затенённых областей, за пределами зоны допуска. Это не означает полного совпадения всех граничных пикселей: необработанный IoU составляет от 0.96786 до 1.0, а расхождения у края особенно заметны при 0.25°.

Следующая таблица содержит **сырые измерения центрального профиля** в единицах калибровочной сцены. Отрицательное смещение конца означает укорочение тени относительно аналитического профиля. Нулевое число означает совпадение классифицированных пикселей профиля, а не доказанную нулевую физическую погрешность.

| Случай | Обнаруженный отрыв у основания | Смещение конца | Принятый допуск вдоль тени |
|---|---:|---:|---:|
| Утренний объём целиком | 0 | 0 | 2.5202 |
| Утренний контакт стены | 0 | Вне кадра | 0.2577 |
| Летний полдень | 0 | 0 | 0.07691 |
| Зимний полдень | 0 | 0 | 0.2783 |
| Круглый столб, 0.25° | 0 | −0.7461 | 6.1261 |
| Контакт стены, 0.25° | 0 | Вне кадра | 2.0482 |
| Удалённый конец утренней тени | Основание вне кадра | +0.015625 | 0.4182 |
| Удалённый конец тени, 0.25° | Основание вне кадра | +0.265625 | 3.2807 |

Для контакта корректный вывод — **отрыв больше принятого допуска не обнаружен**. Нельзя заменять это формулировкой «контакт точен до 7.8 мм», даже когда размер экранного пикселя равен 0.0078125 единицы и измеренный отрыв получился нулевым. Аналогично смещение +0.015625 в одном профиле не даёт гарантии сантиметровой точности всей утренней тени.

Обе удалённые стены отсутствовали во фрустуме основной камеры, но были переданы в shadow pass. Глубина солнечной камеры составила около 2764.69 и 2323.55 единицы соответственно; положения затеняющих объектов вошли в near/far. Проверка поэтому подтверждает работу удалённого источника тени в этих сценах, а не только правильное направление освещения видимого объекта.

Негативные контроли были обнаружены по содержательным причинам:

- При `normalBias = 0.55` тень исчезла из увеличенного фрагмента ожидаемого утреннего конца: полнота ожидаемой тени упала до нуля, проверка профиля не прошла. Номинальная проекция такого смещения на землю — около 15 единиц.
- При `depthBias = -0.08` появился отрыв **2.2890625 единицы**, превышающий допуск 0.2577; доля расхождений уверенной области составила около 27.11%.

Это подтверждает, что успешный результат рабочих случаев не вызван нечувствительным критерием, принимающим произвольную тень.

## Запуск после подготовки v31

Файлы:

- `tools/qa-v31/solar-shadow-gpu-harness.html` — сам браузерный тест;
- `tools/qa-v31/solar-shadow-gpu-native.cjs` — последовательный запуск и сохранение результатов.

Если HTTP-сервер обслуживает **корень проекта**, страница работает по своему штатному пути:

```sh
node tools/qa-v31/solar-shadow-gpu-native.cjs solar-shadow-v31 \
  'http://127.0.0.1:PORT/tools/qa-v31/solar-shadow-gpu-harness.html'
```

Если сервер обслуживает только **dist**, нужно скопировать HTML теста рядом с `dist/index.html` и явно указать базу импортов. При этом драйвер остаётся в `tools/qa-v31`:

```sh
node tools/qa-v31/solar-shadow-gpu-native.cjs solar-shadow-v31 \
  'http://127.0.0.1:PORT/solar-shadow-gpu-harness.html?dist=./'
```

Вместо `PORT` указывается порт изолированной установленной v31. Не запускать одновременно с другой GPU-проверкой на том же Mac.

По умолчанию используются уже проверенные пути существующего Mac QA:

```text
RODINA_PUPPETEER_PATH:
/Users/n1estate/.npm/_npx/4b4c857f6efdfb61/node_modules/puppeteer

RODINA_CHROME_PATH:
/tmp/rodina-reference-qa-v26/chrome-arm64
```

Пути можно заменить одноимёнными переменными окружения. Драйвер сохраняет отдельный профиль Chrome в папке результата, отключает HTTP-кэш страницы, выполняет случаи последовательно и закрывает браузер после завершения. Он не вносит изменений в приложение и не устанавливает новую версию.

Для повторения только определённых случаев можно передать третьим позиционным аргументом имена через запятую:

```sh
node tools/qa-v31/solar-shadow-gpu-native.cjs solar-shadow-v31-contact \
  'http://127.0.0.1:PORT/solar-shadow-gpu-harness.html?dist=./' \
  'user-dawn-contact-wall,control-wrong-depth-bias'
```

Сокращённый запуск проверяет только перечисленные случаи, поэтому его нельзя представлять как прохождение всей сетки.

CPU-проверка работает без браузера и без установки Puppeteer:

```sh
node tools/qa-v31/solar-shadow-gpu-native.cjs --review
```

## Что именно измеряется

Для каждого случая строятся известный замкнутый объём и горизонтальная принимающая плоскость `y=0`. В независимой **калибровочной** сцене для удобства назначено `1 world unit = 1 м`. Поэтому названия «стена 100 м» и «тень 2.727 км» в сетке теста относятся именно к этой системе единиц. Сам WebGL оперирует безразмерными мировыми координатами.

В рабочем проекте другая географическая шкала: `geoFrame.scale.metersPerFixedWorldUnit = 1.1099621033 м / world unit`. Одинаковый численный горизонтальный сдвиг на карте поэтому переводится в метры умножением на 1.1099621033. Стена высотой 100 world units из изолированного теста не является доказательством тени конкретного 100-метрового корпуса проекта. Если все оси модели приведены к одному физическому масштабу, реальная высота 100 м должна быть задана примерно как 90.0932 world units; соответствие фактических высот корпусов проверяется отдельно.

Для ясности ниже дан **только перевод единиц** четырёх допусков: это не новый замер полной сцены и не допуск для всех ракурсов карты.

| Допуск | В калибровочных world units | Такой же численный сдвиг в горизонтальной шкале проекта |
|---|---:|---:|
| Утренний контакт | 0.2577 | около 0.2860 м |
| Утренний удалённый конец | 0.4182 | около 0.4642 м |
| Контакт при 0.25° | 2.0482 | около 2.2735 м |
| Удалённый конец при 0.25° | 3.2807 | около 3.6414 м |

В обзорном ракурсе реального квартала принимающая область имеет другие размеры, следовательно, меняются размер texel и пространственный допуск. Калибровочный результат нельзя переносить на весь обзор без расчёта его собственного разрешения. Солнечные углы при корректном равномерном масштабировании не меняются.

Камера ортографическая и смотрит вертикально вниз. Горизонтальный экранный вектор направлен вдоль тени, вертикальный — поперёк. Два размера пикселя явно сохранены в отчёте; соотношение сторон камеры соответствует рендеру, масштаб по осям не искажается.

Используется белый `MeshLambertMaterial`. Калибровочный объект пишет глубину в настоящий shadow pass, но не пишет цвет и глубину в основной проход камеры. Это позволяет измерить принимающую поверхность, не принять видимую крышу объекта за тень. Область непосредственно под основанием объекта исключена из сравнения.

Тест вызывает реальный `rig.set()` с вычисленными азимутом и видимой высотой, затем `rig.focus(camera)` с настоящей геометрией и принимающей областью. После подбора камеры рендерятся два одинаковых кадра:

1. Объект отбрасывает тень.
2. У того же объекта выключено только `castShadow`.

Камера, источник света, границы shadow camera и геометрия между кадрами не меняются. Для измерения выключена фоновая полусфера, не применяется tone mapping. Географическое направление, интенсивность прямого света и существующий алгоритм shadow mapping сохраняются. Это выбор условий измерения формы тени, а не проверка художественной яркости стандартной сцены.

Пиксели считываются непосредственно через WebGL `readPixels`. Значения sRGB переводятся в линейное пространство, вычисляется отношение яркости «с тенью / без тени»; порог тени — 0.5. Это исключает перенос границы из-за различной яркости солнца в разные даты. Проверяется, что контрольный незатенённый кадр действительно освещён и не является чёрным изображением.

Ожидаемая тень получается независимыми уравнениями пересечения луча с прямоугольным параллелепипедом либо цилиндром. Цилиндр отрисован 128 сегментами; его максимальное радиальное отличие от аналитического круга сохранено отдельно. Направление луча независимо собирается из истинных географических осей, азимута и высоты, после чего сравнивается с направлением настоящего rig.

Реальные даты рассчитываются для 55.6367° N, 37.3525° E. Зимний и летний полдень — вычисленный солнечный полдень 21 декабря и 21 июня 2026 года. Угол 0.25° обозначен отдельным синтетическим калибровочным условием и не выдаётся за определённое время наблюдения.

| Калибровка 0.25°, круглый столб | 1 м | 229.182 м | 0.12436 м | Круглый контур и длинная тень |
| Калибровка 0.25°, контакт стены | 3 м | 687.545 м | 0.0078125 м | Контакт при почти горизонтальном свете |

Его глубина должна входить в near/far солнечной камеры. Таким образом, чёрное пятно непосредственно видимого объекта не может подменить требуемую удалённую тень.

## Разрешение и критерии

Размер пикселя конечного изображения не равен точности тени. Тест вычисляет якобиан преобразования горизонтальной принимающей плоскости в light-space XY и обращает его. Это даёт размер texel shadow map в мировых координатах принимающей поверхности. Вдоль тени он растёт примерно как `1 / sin(elevation)`.

Зона допуска для контура задаётся явно: **три проецированных texel PCF и два пикселя принимающего изображения** по каждой оси. Это консервативный критерий данной GPU-проверки, а не заявленная инженерная точность движка.

Например, при текущих размерах 4096×4096:

- увеличенный контакт в 07:12: допуск вдоль тени около 0.258 м;
- удалённый конец тени в 07:12: около 0.418 м;
- увеличенный контакт при 0.25°: около 2.048 м;
- удалённый конец тени при 0.25°: около 3.281 м.

Это расчётные допуски CPU-проверки текущего fitter; фактические значения повторно записываются после GPU-отрисовки. Они показывают, почему миллиметровый пиксель увеличенного вида не позволяет обещать миллиметровую тень у горизонта.

Точки, целиком находящиеся дальше допуска от ожидаемой границы и основания объекта, проверяются отдельно. Для них допускается не более 1% общих расхождений, не более 2% пропущенной ожидаемой тени и не более 1% ложной тени. Требуется наличие ненулевой уверенно затеняемой области, поэтому пустой результат не может пройти проверку.

Дополнительно измеряются начало и конец тени на центральном поперечном профиле. Отрыв от основания и смещение видимого конца должны укладываться в указанный пространственный допуск. Сохраняются и необработанный IoU масок, и карта пограничных расхождений; сам по себе IoU не является единственным критерием.

## Негативные контроли

Два дополнительных случая намеренно меняют значения **только внутри QA-сцены после вызова настоящего rig**:

- `control-wrong-normal-bias`: `normalBias = 0.55` в увеличенном удалённом конце утренней тени;
- `control-wrong-depth-bias`: `bias = -0.08` в увеличенном контакте утренней стены.

Их ожидаемый результат — `CONTROL_DETECTED`: геометрический критерий должен отвергнуть испорченную тень при исправном WebGL и наличии объекта в shadow pass. Если плохая тень принимается, общий тест провален. Значения этих контролей не записываются в runtime и не являются предложением настройки освещения.

## Результаты native-запуска

Драйвер создаёт папку `tools/qa-v31/OUTPUT_LABEL` с:

- `metrics.json`: сведения о GPU, SHA-256 реально загруженных runtime-модулей, солнечные углы, размеры, camera fit, bias, разрешение, показатели и критерии каждого случая;
- четырьмя PNG на случай: настоящий кадр с тенью, контрольный кадр без тени, независимая ожидаемая маска и карта расхождений.

Цвета карты: синий — совпавшая тень; белый — совпавшее солнце; красный — отсутствующая тень вне зоны допуска; фиолетовый — лишняя тень вне допуска; жёлтый — расхождение в зоне дискретизации; серый — исключённое основание объекта.

Общий PASS требует прохождения всех выбранных рабочих случаев, обнаружения выбранных негативных контролей, отсутствия ошибок WebGL/страницы и признаков аппаратного GPU. SwiftShader, llvmpipe и другие программные рендереры не принимаются как native GPU-проверка.

Эта процедура не измеряет FPS, полную модель растительности, точность зданий, оптические материалы или нормативную инсоляцию квартир. Она закрывает конкретный риск: правильно ли новый солнечный rig отрисовывает геометрическую тень известных размеров, включая контакт, низкое солнце и затеняющий объект далеко за кадром.
