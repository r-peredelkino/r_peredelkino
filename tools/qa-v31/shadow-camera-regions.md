# Фактические области получения теней — v31

## Решение для интеграции

Владелец интеграции выбрал две явно переключаемые области GPU-теней:
**«Квартал (детальнее)»** и **«Район (шире)»**. Они ограничивают
получателей теней. **Все затеняющие объекты сцены остаются в расчёте
глубины солнечной камеры при любом выборе.**

Выбор `context`/`transport` должен включать район; основные ракурсы
квартала — квартал. Область построена по существующим объектам сцены,
а не по произвольному кругу возле зрителя. Пользовательский выбор
обозначает действительную область гарантированного покрытия теневой
карты. За её пределами полнота GPU-теней не гарантируется.

Точечный расчёт прямого солнца и солнечных часов должен проверять
видимость по всей затеняющей геометрии, независимо от выбранной области
GPU-теней. Размер shadow map, область получателей и дискретизация
картинки не должны влиять на численный результат в выбранной точке.

Для отдельного вида квартиры получателем служит полный bounding box
этой квартиры: мебель, стены, пол и скрытые варианты потолка/полных стен.
Источники её затенения берутся из объединения квартиры и всего комплекса.
Так сохраняется детализация окон и внутренних поверхностей, даже если
перспективная камера имеет far=1400 и показывает дальнее окружение.

Этот документ проверяет геометрию областей и матрицы. Применение
переключателей в интерфейсе и GPU-качество проверяются интеграционно
отдельно.

## Откуда получены границы

Скрипт `shadow-camera-regions.mjs` создаёт фактическую модель v31,
собирает границы обычных и instanced meshes с их мировыми
преобразованиями и сохраняет `shadow-camera-regions.json`.
Исходные геометрия, материалы, позиции и флаги не изменяются.
Bounding box вычисляется один раз, включая скрытую сезонную геометрию.

Все числа ниже — **world units**, по сохранённой регистрации
1 world = 1,109962103262469 м. К границам добавлен технический запас
0,5 world со всех сторон; это не расширение исходной геометрии.

| Область | Min XYZ | Max XYZ | Размер X/Z |
|---|---|---|---:|
| Квартал + roadside | `[-131.153366, -3, -148.524216]` | `[119.376823, 96.335, 140.500046]` | 250,530 / 289,024 |
| Застроенный район без лесного фона | `[-518.485413, -3, -528.760254]` | `[414.858490, 96.335, 252.500854]` | 933,344 / 781,261 |
| Все получатели без огромной подложки и неба | `[-986.972343, -3, -528.760254]` | `[414.858490, 96.335, 1040.231615]` | 1401,831 / 1568,992 |
| Все затеняющие объекты, для любой области | `[-885.005771, -3, -501.215481]` | `[400.407678, 96.335, 940.363357]` | 1285,413 / 1441,579 |

Квартальная область — объединение `receiveShadow` объектов основной
модели, за исключением следующих корней:

- `model.neighborhood.group` — улицы и все соседние кварталы;
- `model.neighborhood.forestGroup` — лес до дальнего горизонта;
- `model.traffic.group` — транспорт района.

Из первой исключённой группы обратно включается
`model.neighborhood.roadside.group`: **`Reference forecourt roadside ·
parking, islands and street furniture`**. Эта группа содержит парковки,
островки и предметы благоустройства перед участком. Дорожные покрытия
внутри полученного объёма тоже получают тени, независимо от их группы.
Полный протяжённый транспортный коридор и соседние дома гарантированно
охватывает режим района.

Квартальная область полностью содержит все проверенные получатели
самого ЖК: пять жилых корпусов и офисную башню по всей высоте,
арену, стилобат, двор, коммерческие галереи, террасы, офис продаж,
подъезд за ним и променады. Ничего из этих частей не обрезается.
Её экстремумы задают:

- минимальный X — группа публичного пространства и променада;
- минимальный Z — roadside;
- максимальный X — исходная подложка и покрытия участка;
- максимальный Z — территория офиса продаж и будущего подъезда;
- максимальный Y — реальные верхние детали жилых башен;
- минимальный Y — нижняя грань исходной подложки участка.

Районная область включает все получатели, кроме лесной группы,
огромной подложки и декоративного неба. Она сохраняет все 11 соседних
домов, обслуживающие здания, улицы, локальные проезды и метро.

### Рекомендуемая схема сбора через существующий API

```js
const below = (object, ancestor) => {
  for (let p = object; p; p = p.parent) if (p === ancestor) return true;
  return false;
};

const backdrop = model.neighborhood.forestGroup
  .getObjectByName('Continuous woodland ground');
const excludeBackground = object => object === backdrop;
// Флаги excludeFromSolarShadow у sky meshes collector уже учитывает сам.
const all = collectSolarShadowBounds(model.root, {ignore: excludeBackground});

const quarterObject = object => {
  if (below(object, model.neighborhood.roadside.group)) return true;
  return ![
    model.neighborhood.group,
    model.neighborhood.forestGroup,
    model.traffic.group,
  ].some(group => below(object, group));
};
const quarter = collectSolarShadowBounds(model.root, {
  ignore: object => excludeBackground(object) || !quarterObject(object),
}).receiverBounds;
const district = collectSolarShadowBounds(model.root, {
  ignore: object => excludeBackground(object)
    || below(object, model.neighborhood.forestGroup),
}).receiverBounds;

const fitter = createSolarShadowCameraFitter(sun, {
  casterBounds: all.casterBounds,
  receiverBounds: quarter,
});
fitter.fit({camera, direction, receiverBounds: selected === 'district'
  ? district : quarter});
```

Это операции при построении/изменении сцены, не каждый кадр.
При подготовке квартирной сцены её caster bounds объединяются
с `all.casterBounds`; receiver bounds берутся из квартиры целиком.
Пример намеренно не использует caster bounds квартального сбора:
они исключили бы нужные дальние здания и лес.

## Объекты, раздувавшие исходный охват

**`Continuous woodland ground`** находится в группе
**`Continuous mature pine forest behind the sales office`**.
Это четырёхугольная фоновая подложка ±2600 в старых плановых осях.
Её мировой bbox без запаса:

```text
min [-3676.58203125, -1.42, -3676.58203125]
max [ 3676.58203125, -1.42,  3676.58203125]
```

Она получает, но не отбрасывает тени. Её исключение из bounds не
меняет кастеров. Отдельная **`Dark continuous woodland floor behind
the pine edge`** остаётся гораздо меньше, но всё ещё охватывает
XZ `[-924.365906,-387.081909]…[355.540466,998.261047]` на y=−0,68.
Поэтому одного исключения первой подложки недостаточно для детализации
прогулки: лесные получатели также не входят в выбранный квартал/район.

Декоративное небо — три безымянных instanced meshes в
**`Clouds, birds and residents`**:

| Содержимое | Количество instances | Индекс дочернего объекта при аудите | Y без запаса |
|---|---:|---:|---:|
| Части облаков | 35 | 58 | 137,525…168,640 |
| Тела птиц | 9 | 59 | 102,933…127,078 |
| Крылья птиц | 18 | 60 | 103,035…126,976 |

Исходные родители называются **`Drifting cloud`** и **`Bird in flight`**.
Дочерние индексы приведены только для диагностики этой сборки;
использовать их или высотный порог в runtime не следует. Исправление
в месте создания `bucket.sky` задаёт `receiveShadow=false` и
`userData.excludeFromSolarShadow=true`. Полезные скрытые сезонные
деревья и стены этим фильтром не исключаются.

## Численная оценка детализации

Проверена исходная перспектива площади; прогулка использует фактические
FOV=70°, near=0,08, far=900 и тестовый aspect=1,5. Позиция прогулки
`[14,1.68,-102]`, взгляд в `[3,1.68,-86]`. Сравниваются летний и зимний
полдень, высота 0,25° с востока и запада. Эти углы — явные тестовые
входы для геометрии камеры, не новая астрономическая эфемерида.

| Вид и область | Ширина shadow camera по проверенным углам | Максимум world/texel при 4096² |
|---|---:|---:|
| Площадь, квартал | 136,160–223,114 | 0,05447 |
| Прогулка, квартал | 202,130–246,276 | 0,06013 |
| Та же прогулка, район | 365,598–614,052 | 0,14991 |
| Та же прогулка, все получатели без неба и огромной подложки | до 1256,600 | 0,30679 |
| Квартира 1-59, только её полный объём | 12,109–14,043 | 0,00343 |
| Квартира 1-81, только её полный объём | 12,109–21,902 | 0,00535 |

В квартирных случаях far=1400. Проверены исходные обзорные положения
камеры и отдельные тестовые взгляды из центров существующих окон.
Последние выведены из плана и не выдаются за сохранённые пользовательские
позиции камеры. Bbox квартир с запасом:

- 1-59: `[-5.981851,18.62,-55.962222]…[3.209019,22.52,-45.776793]`;
- 1-81: `[-5.637258,24.62,-75.925844]…[6.012908,28.52,-57.432632]`.

При 2048² размер texel вдвое больше, при 1024² — вчетверо больше.
Это разрешение проекции, а не гарантия аналогичной точности геометрии,
границы PCF-тени или времени инсоляции.

Результат **420 сочетаний камеры, области и солнечного направления**:
ни одного выхода видимого получателя за теневую камеру, ни одного
выхода полного caster depth за near/far. Все фактические квартальные
получатели целиком находятся в квартальном и районном bbox.
Кастеры до и после фильтра фона совпадают точно.

`shadow-camera-regions.json` сохраняет SHA входных модулей и численные
результаты. `shadow-camera-regions-sky-before.json` фиксирует обнаруженные
параметры sky до исправления. FPS, растровое качество PCF и отсутствие
акне/отрыва теней этим CPU-аудитом не измеряются.
